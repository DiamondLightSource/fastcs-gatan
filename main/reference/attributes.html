Attributes#

Attributes and commands grouped by the SerialEMCCD plugin capability they belong to. Plugin source references are to SerialEMCCD at commit 4d6e4b1; the calls themselves are listed in SerialEMCCD plugin calls.

Names#

EPICS (CA)

REST

Attribute

<id>:<SubController>:<Name>, e.g. GATAN:Acquisition:DoseFracBusy

/<id>/<sub-controller>/<name>, e.g. /GATAN/acquisition/dose-frac-busy

Root attribute

<id>:<Name>, e.g. GATAN:DmVersion

/<id>/<name>, e.g. /GATAN/dm-version

Read-write

setpoint PV, plus _RBV readback

PUT {"value": ...}, GET to read

Command

write 1 to the PV; failure gives a MAJOR alarm

PUT to //<id>/... (double slash)

<id> is the controller id in the YAML config. The PV column in the tables below leaves out the <id>: prefix.

The sections follow the plugin’s capability areas. The attribute groups in the code (which organise the EPICS screens) don’t always match them; each section names the code’s sub-controller and group.

The “Plugin side” column says whether an attribute is an argument or a result of a plugin call, or driver if it exists only in fastcs-gatan.

Exposure parameters (GetAcquiredImage arguments)#

GetAcquiredImage is the plugin’s one acquisition call; single images, continuous acquisition and dose fractionation all use it. What one call does is decided in TemplatePlugIn::GetImage (L878): frame saving is on only if SetK2Parameters2 turned on both dose fractionation and frame saving and SetupFileSaving2 gave a folder and a name (L897-L899); continuous mode needs processing above 7 and frame saving and alignment off (L972-L988).

In the code, the parameters below are in acquisition, group Acquire, along with the single-image attributes.

Mode

Set up by

What the plugin does

Sent to fastcs-gatan

Single image

processing 0-7, frame saving off

One exposure; stops continuous mode first if it is running

One image per call

Continuous

processing > 7 (continuous bits), frame saving and alignment off

First call starts an acquisition loop in a plugin thread; each later call copies out its newest frame (GetContinuousFrame, L3587); StopContinuousCamera ends it

One image per call; frames the loop takes between calls never leave the DM PC

Dose fractionation

SetK2Parameters2 (dose fractionation and frame saving on) and SetupFileSaving2 first

One exposure split into sub-frames, written to disk on the DM PC

One image: the sum. The sub-frames are never sent

Every call transfers one full image over the network, and that is the slow part. The plugin sends 2 bytes per pixel in chunks of up to 32 MiB, waiting for a handshake from the client after each one (SocketPathway.cpp L37, L849-L878). A K3 frame at physical pixel size (5760 × 4092) is 47 MB, two chunks: at least 0.4 s at 1 Gbit/s, before any processing time. A super-resolution frame would be four times that.

What GetAcquiredImage can do on the plugin side, briefly (✓ = used by fastcs-gatan):

  • ✓ exposure time, binning, processing (unprocessed, dark-subtracted, gain-normalised), readout area

  • ✓ shutter selection; shutter delay, settling time, divide-by-2 and DM correction flags (sent as 0)

  • continuous mode with a quality setting (planned)

  • ✓ dose fractionation with frames saved as MRC, MRCS or TIFF (LZW or ZIP) on the DM PC; further options such as 4-bit packing, summing frames before saving and a gain-normalised sum, set through flag bits

  • early return (send the sum back before saving finishes), deferred sums, frame alignment in the plugin, tilt sums: out of scope

Dose fractionation (frames saved on the DM PC)#

acquisition, group FrameSaving.

acquire_dose_fractionated runs, in a worker thread, with nothing else allowed on the connection in between:

  1. SetK2Parameters2 with dose fractionation and frame saving on, the frame time, and frame alignment off

  2. SetupFileSaving2 with the folder, name, pixel size and flags (one stack file, not one file per frame)

  3. GetAcquiredImage: the exposure; the plugin saves the sub-frames and returns their sum

  4. GetFileSaveResult: frames saved and saving error

  5. SetK2Parameters2 with dose fractionation and frame saving off again

Read mode, scaling, hardware processing, rotation/flip and k2_flags come from group ReadMode; size, binning, processing and shutter from the exposure parameters.

Shutter and settling#

SetShutterNormallyClosed and SetNoDMSettling are implemented on the connection but have no attributes yet.

Not covered#

Plugin capabilities fastcs-gatan does not use:

  • DM scripting: ExecuteScript, QueueScript

  • Dark and gain references, defects: GetDarkReference, GetGainReference, FreeK2GainReference, GetDefectList

  • Frame alignment in the plugin: SetupFrameAligning, FrameAlignResults, MakeAlignComFile, IsGpuAvailable, ReturnDeferredSum, GetTiltSumProperties, SaveFrameMdoc

  • DigiScan/STEM: GetDSProperties, AcquireDSImage, ReturnDSChannel, StopDSAcquisition

  • Other: WaitUntilReady, SetDMVersion, SetDebugMode

Known limitations#

As the code stands:

  • Continuous acquisition is not implemented; its commands fail.

  • Group names differ from the plugin areas: dose_frac, frame_time and save_frames are SetK2Parameters2 arguments but sit in group FrameSaving, not ReadMode; group Acquire holds both the shared exposure parameters and the single-image attributes.

  • last_dose_rate and the other Status values are read only at startup.

  • last_frame is decoded as unsigned 16-bit; whether the plugin’s data should be read as signed or unsigned is not settled. Frames larger than 4096 × 5760 (super-resolution) don’t fit it.

  • acquire_image blocks the driver until the image has arrived, so nothing else updates meanwhile.

  • Shutter and settling calls have no attributes, and the shutter delay, settling, divide-by-2 and corrections arguments of GetAcquiredImage are always 0.

  • Plugin version: the source cited here is plugin version 121; check plugin_version on the real system, which may run an older plugin.
